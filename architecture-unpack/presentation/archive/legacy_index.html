Strategic Context · Rebuilding Core LMS

Moving Beyond Naive LLM Prompting

Consumer lending infrastructure requires statutory compliance (Truth in Lending Act / Reg Z) and double-entry accounting balances where $\Delta = \$0.00$. Standard generative copilots introduce four critical failure modes that demand an industrialized deterministic substrate.

1The Failure Modes of Probabilistic AI

  • Context Drift & State Amnesia: Unconstrained chat prompts invent non-existent APIs and drop regulatory lending constraints.
  • Unbounded Ambient Authority: Giving LLMs ambient cloud credentials risks accidental database wipes or live payment rail execution.
  • Circular Confirmation Bias: When an agent authors both implementation and test, it writes tests that assert against its own bugs.
  • Non-Deterministic Builds: Probabilistic outputs yield irreproducible code, flaky CI, and untraceable regressions.

2The Deterministic Substrate on GCP

  • Human Governed, Machine Executed: Qualified Zip engineers specify intent and hold every consequential gate.
  • Constitutional Separation: "Author and judge are never the same persona." Test generation has zero code visibility.
  • Single-Task Disposable Sandboxes: Ephemeral Cloud Run sandboxes with 15-minute down-scoped IAM tokens.
  • Immutable Signed Ledger: Every state transition, disagreement, and gate evaluation committed to Cloud SQL PostgreSQL.
The Sovereign Waterline Principle: Zip permanently owns everything Above the Waterline (domain methodology, golden specs, evaluation test banks, invariants, and legal verification evidence). Google Cloud provides commodity infrastructure Below the Waterline (GKE, Cloud Run, Temporal, Cloud SQL, Vertex AI). Zip buys models as utility, but builds the factory as an enduring operational asset.
Key framing for Chris & Eric: We are not selling a magic black box or staff augmentation. We are constructing an industrialized software manufacturing plant that Zip owns in perpetuity.

Act 1: Concepts & Phases · Execution Framework

The Recursive Double Diamond within Every Phase

Rather than treating the British Design Council’s Double Diamond as a static, multi-month project management waterfall, the Zip factory applies the Double Diamond recursively within every single phase.

DIAMOND 1 · DIVERGENT

1. Discover

Fan-out context gathering, legacy Azure monolith C# AST parsing, regulatory requirement retrieval, and edge-case discovery.

DIAMOND 1 · CONVERGENT

2. Define

Synthesizing insights into rigid, machine-verifiable JSON Schema contracts (Artifacts A–F). Establishing mathematical invariants.

DIAMOND 2 · DIVERGENT

3. Develop

Multi-agent parallel codegen; isolated zero-code-access test authoring; adversarial red-team probing in ephemeral sandboxes.

DIAMOND 2 · CONVERGENT

4. Deliver

Automated verification against non-negotiable exit gates; cent-for-cent ledger drift proof ($0.00); cryptographic sign-off.

The Compounding Advantage for Zip: Skips neither discovery nor verification. Traditional LLM codegen jumps straight from vague prompt to code (skipping Diamond 1), resulting in massive rework. By enforcing convergence before code generation, requirements are mathematically proven unambiguous before any code is generated.
Every phase renders an interactive Directed Acyclic Graph (DAG) in the Explorer.
Key insight: Applying Double Diamond recursively prevents the classic AI failure of "prompt-to-code-with-no-bounds".

Act 2: Platform Architecture · GCP Blueprint

The 5-Tier Cloud Architecture on Google Cloud Platform

Deploying an industrialized, sovereign cloud substrate on GCP: stripping agents of persistent ambient authority and enforcing zero-trust execution across disposable containers.

1Perimeter & Control Plane

Tier 1 (Perimeter): GitHub Enterprise CODEOWNERS branch protection, Jira Cloud Read-Only MCP, Slack Enterprise kill switch, GCS WORM retention bucket.

Tier 2 (GKE Control Plane): GKE Enterprise Private Cluster with Workload Identity, Temporal.io durable orchestration engine, and Cloud SQL PostgreSQL 16 JSONB backplane.

2Sandboxes & Vertex Gateway

Tier 3 (Execution Sandboxes): Disposable Cloud Run containers with read-only root filesystems, volatile tmpfs, and ephemeral 15-minute OAuth2 tokens.

Tier 4 (Vertex AI Gateway): Intelligent multi-model routing: Gemini 1.5 Pro (2M context for specs/statutes), Claude 3.5 Sonnet (idiomatic codegen), Gemini Flash (AST linting/eval triage).

Tier 5: Target Core, Service Mesh & Legacy Coexistence

GKE Service Mesh (Istio Envoy Proxies): Suppresses all outbound network calls during pipeline runs, preventing accidental SMS alerts, live bureau queries, or payment rail triggers. Cloud Pub/Sub Dual Ingestion: Mirrors live production transactions from Azure monolith. BigQuery Reconciliation: Verifies double-entry ledger balance ($0.00 delta) over 14 consecutive clean days.

Architecture highlight: Notice the Envoy outbound suppression proxy. The agents literally cannot trigger an external payment rail even if they try.

Act 3: FDE Statement of Work · Pilot Dry Run

Pilot Target: Repayments & Loan Amortization Engine

Selected as the pilot dry run for core banking rigor: requires exact decimal mathematics, double-entry ledger balance, statutory Truth in Lending Act disclosures, and historical replay against Snowflake/Databricks.

Why Repayments Was Chosen

  • Zero Tolerance for Float Errors: Floating-point math introduces fractional cent errors. Must use exact arbitrary-precision decimal representation.
  • Statutory APR Calculations: Truth in Lending Act (Reg Z) requires exact disclosure schedules and US state interest rate cap compliance.
  • Double-Entry Accounting: Every debited repayment must balance against principal, fee, and interest ledgers with exact zero variance.

Historical Production Replay ($0.00 Drift)

  • 50,000 Active Accounts: Replaying 3 years of actual production ledger transactions from Snowflake/Databricks.
  • 4-Class Divergence Taxonomy: Categorizes differences into Exact Match, Expected Refactoring, Legacy Anomaly, or Bug.
  • 14-Day Zero-Cent Proof Gate: Requires 14 consecutive clean days of zero financial drift before cutover sign-off.
The Ultimate Financial Proof: If the autonomous factory can manufacture the Repayments Engine and replay 50,000 complex amortizing loans with $0.00 zero-cent variance, the factory has proven it can build any domain in the banking estate.
Financial gravity: If you build Decisioning or Customer first, you get fuzzy NLP answers. Repayments is mathematically pure: either the ledger balances to the penny, or it fails.
