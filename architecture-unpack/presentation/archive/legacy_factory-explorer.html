THE CORE PROBLEM

The Failure Modes of Naive LLM Prompting

Consumer lending software operates under statutory mandates (Truth in Lending Act / Reg Z, ECOA / Reg B, FDCPA) and penny-perfect double-entry accounting balances ($\Delta = \$0.00$). Standard generative AI copilots suffer from four critical failure modes:

  • ❌ Context Drift & State Amnesia: Chat sessions hallucinate non-existent APIs and drop lending boundary conditions.
  • ❌ Unbounded Ambient Authority: Long-lived credentials risk unintended live database mutations or payment rail execution.
  • ❌ Circular Confirmation Bias: When an agent authors both code and test, it asserts against its own flawed assumptions.
  • ❌ Irreproducible Builds: Probabilistic output introduces non-deterministic flake into mission-critical pipelines.
THE ARCHITECTURAL SOLUTION

The Industrial Autonomous Software Factory

The Zip Agentic Factory treats software as an industrialized, manufactured product anchored to three non-negotiable principles:

  • 🛡️ Human In, On & Over the Loop: Senior human engineers specify intent and hold every consequential deployment gate.
  • ⚖️ Constitutional Separation of Powers: "Author and judge are never the same persona." Test generation is 100% isolated from code.
  • 🔒 Deterministic Cloud Substrate: Ephemeral Cloud Run sandboxes, 15-minute IAM token rotation, and hard Envoy side-effect suppression.
  • 📐 Compounding Verification: Every iteration produces an immutable audit evidence pack for bank regulators.

Concepts, Phases & Constitutional Architecture

Act 1 bridges the initial five handwritten whiteboard scans into strongly-typed engineering contracts. It resolves the "missing Phase 4" anomaly by establishing Phase 4: Review & Verification, codifies the 7 macro pipeline phases, and establishes the Recursive Double Diamond architecture.

💎 1. The Recursive Double Diamond within Every Phase

Rather than applying the Double Diamond as a static multi-month waterfall, the Zip factory runs Discover ➔ Define ➔ Develop ➔ Deliver micro-cycles inside every single phase:

  • Discover (Divergent): Broad context gathering, code archaeology of Azure monolith, AST extraction.
  • Define (Convergent): Rigid synthesis into strongly-typed JSON Schema contracts (Artifacts A–F).
  • Develop (Divergent): Multi-agent parallel build; zero-code test authoring in isolated sandboxes.
  • Deliver (Convergent): Gate verification, ledger balance proof ($0.00 delta), cryptographic sign-off.

📦 2. The 10 Strongly-Typed Artifacts & DER Model

Upgraded informal file references into rigid schema contracts with bidirectional traceability:

  • Artifact A: Golden PRD & Invariants Contract (Schema-validated intent)
  • Artifact B: Negotiation File Ledger (Disagreement preserved as an artifact)
  • Artifact C: Project Topology & Assignment Matrix (Work rungs & sandbox specs)
  • Artifact D: Service Implementation Build & AST Report (Generated source & manifests)
  • Artifact E: Independent Test Suite (Zero-code-access spec-derived assertions)
  • Artifact F: Verification Evidence & Compliance Audit Pack (Regulator audit trail)

👥 3. Separation of Powers: 28 Personas & 111 Machine Skills

Constitutional Rule: "Author and judge are never the same persona." Personas are strictly decoupled across 6 families: Family A (Product Intent), Family B (Architecture), Family C (Code Generation), Family D (Quality Judges & Red Team), Family E (DevOps & Substrate), and Family F (Governance & Security).

Platform Architecture & Substrate Specification

Act 2 establishes the production substrate for the Zip Agentic Factory on Google Cloud Platform. Agents are stripped of persistent ambient authority and execute within disposable Cloud Run sandboxes governed by GKE Enterprise and Temporal.

☁️ 1. The 5-Tier Cloud Architecture

  • Tier 1 (Perimeter): GitHub Enterprise CODEOWNERS, Jira Read-Only MCP, Slack Kill Switch, GCS WORM Object Lock bucket.
  • Tier 2 (Control Plane): GKE Enterprise private cluster, Temporal.io workflow engine, Cloud SQL PostgreSQL 16 JSONB backplane.
  • Tier 3 (Execution Sandboxes): Disposable Cloud Run containers with volatile tmpfs, 15m OAuth2 tokens, isolated zero-code test runner.
  • Tier 4 (Multi-Model Gateway): Vertex AI routing to Gemini 1.5 Pro (2M context), Claude 3.5 Sonnet (codegen), Gemini Flash (eval).
  • Tier 5 (Target Core & Mesh): Istio service mesh with hard Envoy side-effect suppression, Pub/Sub dual mirroring, BigQuery $0.00 reconciliation.

⚡ 2. The Tooling & State Membrane

  • Node.js 22 MCP Hub: 71 domain tools across 17 subsystems via Streamable HTTP with Server-Sent Events (SSE) and <wake> protocol.
  • Sovereign State Storage: Cloud SQL JSONB envelope backplane; zero in-memory ephemeral state persistence.
  • Sub-Second Kill Switch: Global Slack webhook propagation terminates containers, revokes IAM tokens, and aborts workflows in <750ms.
  • Adoption of Reference Triad: 14 Invariant Axioms from mission-kit; Threads 2.0 consensus from agentic-network; 3-Layer Architecture from mam.

          EXECUTIVE SCOPING EVALUATION VERDICT: ADEQUATE & VIABLE (WITH DISCIPLINE)

          Is the 8–12 Week Timeline Adequate for 1x Google FDE?

          Yes, the 8–12 week timeframe is adequate and viable — provided there is strict scoping discipline: The 1x Google Field Deployed Engineer (FDE) must be scoped exclusively as the technical spearhead who builds the factory machine and executes a single pilot dry run (Repayments & Loan Amortization Engine). The subsequent 12-month migration of all 5 Loan Management System (LMS) domains and live shadow gating must be executed by Partner FDEs (Quantium) and Zip Senior Engineers (14 SWEs over 9 months).

          The Critical Dividing Line: The Google FDE builds the assembly line and validates the first car through it. Zip and Quantium operate the plant to manufacture the fleet. If the Google FDE is still hands-on at Week 20, knowledge transfer has failed and the enduring Zip asset premise becomes an outsourced dependency.

          Three Delivery Scenarios Evaluated

          8-Week Accelerated Sprint

          "Aggressive Minimum Viable Build"

          Compresses control plane setup, harness, and a synthetic mock pilot into 8 weeks. Feasible only if GCP VPC, IAM, and Vertex AI quotas are 100% pre-provisioned on Day 0.

          Zip Team: 12 Person-Weeks (2 SWEs)

          Handover: Async README & recorded demo
          Trade-Off: Fastest completion, but fragile to enterprise delays. High probability that partner/Zip engineers cannot operate the factory independently without ongoing Google escalations.
          SCENARIO 2 🟡 PRAGMATIC BASELINE

          10-Week Balanced MVP

          "Functional Build + Sample Replay"

          Provides buffer for initial GCP landing zone provisioning, stands up the 10 MVP personas, and runs the Repayments pilot against a 1-month sample of historical transactions.

          Google FDE: 10 Person-Weeks (100%)
          Zip Team: 18 Person-Weeks (2 SWEs + Arch)

          Pilot Scope: 1-Month historical sample replay
          Handover: 2-week compressed pairing

          SCENARIO 3 · RECOMMENDED 🟢 ENTERPRISE DERISKED

          12-Week Sequential Handover

          "Complete Build + Full Replay + 4-Week Partner Transfer"

          UNIVERSAL ADAPTER @APNEX/NETWORK-ADAPTER

          L4 Wire Transport & L7 Session FSM

          Separates raw socket transport from high-level agent session lifecycle, insulating host LLMs from transient cloud disconnects.

          L4 Wire Transport (McpTransport):
          3-State FSM: disconnected → connecting → connected.
          Dual liveness: 30s heartbeat ping + 90s SSE watchdog with classified reconnect triggers.
          L7 Session Client (McpAgentClient):
          5-State FSM: disconnected → connecting → synchronizing → streaming → reconnecting.
          Executes register_role handshake, dedups events, and surfaces actionable wakes (<channel> injection or promptAsync).

          🤝 Threads 2.0: Turn-Alternating Staged Consensus

          How autonomous agents resolve disputes and reach verified alignment without chaotic free-form prompting.

          1. Semantic Intent Tagging

          Every thread message carries a mandatory tag: propose, challenge, concur, synthesize, or park.

          2. Staged Convergence Actions

          Back-and-forth turns accumulate proposed actions in memory. No side-effects land until convergence.

          3. Atomic Commit on Converged

          When both parties agree (converged: true), the Hub commits the staged convergence actions atomically.

          Zip Agentic Factory Adoption Blueprints

          How the 7 factory pipeline phases directly borrow and implement concrete constructs from these sample repositories.

          (1) SPECIFY PHASE FROM MISSION-KIT

          Axiomatic Specification & Claim Discipline

          Challenge: Product Managers produce vague, un-testable specs ("make repayments scalable").
          Adoption Blueprint: Enforce mission-kit's Claim Discipline (every claim tagged Measured or Inferred) + SC1–SC6 machine-validatable schemas + Regulatory Analyst's Statutory Mapping Matrix (Reg Z/B, PCI DSS) before coding begins.

          (2) DISPATCH PHASE FROM AGENTIC-NETWORK

          Deterministic Dispatch & L4/L7 Session FSM

          Challenge: LLM hallucinating task dependencies, duplicate execution, or tool credential leaks.
          Adoption Blueprint: Implement Dispatch as a deterministic policy service (NOT an LLM) using agentic-network's L4 Wire Transport & L7 Session FSM. Issue single-task ephemeral execution tokens via register_role cryptographic handshakes with bounded tool blast radiuses.

          (3) GENERATE PHASE FROM ENTERPRISE DEAL ENGINE

          Neighborhood Rules in Disposable Cloud Run Sandboxes

          Challenge: Microservice agents overwriting cross-tenant data structures or shared modules.
          Adoption Blueprint: Enforce the Enterprise Engine's Neighborhood Rules: an Implementation Engineer in the Repayments sandbox can touch only services/repayments/. Cross-boundary changes require opening a formal Markdown Negotiation file. Run inside disposable Cloud Run sandboxes with read-only root filesystems.

          (4) REVIEW PHASE FROM AGENTIC-NETWORK & MISSION-KIT

          Threads 2.0 & 3-Cycle Stopping Falsifier

          Challenge: Circular disputes between Implementation Engineers (Authors) and Spec Conformance Judges (Judges).
          Adoption Blueprint: Mediate reviews via Threads 2.0 turn-alternating consensus with mandatory semanticIntent tags. Enforce mission-kit's 3-cycle stopping rule: if parties do not converge in 3 cycles on the same evidence, automatically park and escalate to human CODEOWNERS (PL-21).

          (5) VERIFY PHASE FROM MISSION-KIT

          Evidence Quality & Strict Test Isolation

          Challenge: Tests verifying their own mocks rather than true functional integrity.
          Adoption Blueprint: Enforce mission-kit's golden doctrine: "Measure the effect, not the act." A test asserting HTTP 200 is invalid; it must verify that debits equal credits in the PostgreSQL ledger ($0.00 drift). The Isolated Test Engineer authors TDD suites with zero source code access.

          (6) SHADOW GATE PHASE FROM ENTERPRISE & ZIP BLUEPRINT

          BigQuery Telemetry Graph & 4-Class Divergence Taxonomy

          Challenge: Triaging millions of daily mirrored loan repayment transactions against legacy Azure.
          Adoption Blueprint: Ingest both Azure and GCP ledger streams into BigQuery telemetry. The Reconciliation Analyst automatically classifies divergences into the 4-class taxonomy (GCP Bug, Legacy Bug, Rounding/Float, Intentional Spec Deviation). Gate production cutover on 14 consecutive clean shadow days.

          (7) COMPOUNDING PHASE FROM AGENTIC-NETWORK (CALIBRATIONS)

          Calibration Ledger & Compounding Regression Evals (A14)

          Challenge: Knowledge loss and persona prompt drift when foundation models are updated.
          Adoption Blueprint: Maintain a central Calibration Ledger (calibrations.yaml) queryable via deterministic script. Automatically convert escaped defects into permanent regression evals in the Eval Engineer's suite, ensuring cycle N+1 is progressively cheaper and faster.
